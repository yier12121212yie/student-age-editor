# 小游戏库工作台（导演布局的专属功能界面）

「每个功能都有专属界面」重建的第 3 批第一个功能。落在
`frontend/lib/features/minigames/minigames_workbench.dart`，由导演工作台的
「小游戏库」功能（`_DirectorFeature.minigames`）承载；主页「小游戏库」卡片直接进入。

对标把「小游戏库」做成一个**挑选并试玩**的弹窗（选小游戏 → 选关卡 → 试玩数独）；
这里重建为**配置编辑工作台**：管理小游戏定义与关卡参数，并提供原版玩法说明预览。

## 布局（三栏）

| 栏 | 内容 |
| --- | --- |
| 左（260–300） | 搜索 / ＋新建小游戏 / 删除此小游戏 / 小游戏列表（名称、关卡数、编号） |
| 中（自适应） | 小游戏定义 + 关卡区（第 1~5 关切换 + ＋关卡 + 关卡编辑）+ 保存条 |
| 右（≥1080 显示，280–320） | 玩法预览（原版配图 + 玩法提示）+ 统计与引用 |

窄窗（<1080）自动隐藏右栏；<1340 收窄左右栏。

## 小游戏定义（MinigameCfg）

- 名称 `name`、玩法提示 `tips`、背景音乐编号 `bgm`（`AudioCfg` 编号，0 = 无）。
- 编号规则：新建时取全表最大值 +1（起始 ≥ 5）。

## 关卡（MinigameActionCfg）

- 关卡编号 = 小游戏编号 × 100 + 关卡序号（第 1~5 关，匹配游戏内约定）。
- 关卡列表按编号排序，「＋ 关卡」在最后追加一关，「删除此关」删除当前关。
- 每关编辑：精力消耗 `cost`、模式 `mode`、关系要求 `needRelation`（`RelationCfg` 下拉）、
  数值参数 `parms`（逗号分隔 1D 数组）、开场对话 `startTalk`、胜利对话 `winTalk`、
  失败对话 `loseTalk`（`TalkCfg` 编号）、关卡效果 `effect`。
- **关卡效果**统一经「打开积木库」可视化编辑（效果模式），与积木库结果一致。

## 玩法预览

- 从 `GuideCfg` 读取原版玩法配图 `url` 与说明 `tips`（约定放在 `游戏编号 × 100 + 1`），
  配图用 `TexThumb` 呈现，读不到时显示占位。
- 统计与引用：关卡数量、背景音乐、当前关卡消耗 / 关系要求 / 三处对白编号
  （`TalkCfg` 缺失时标注）、关卡效果条数。

## 数据与保存

- **同时编辑两张表**，各自整表读写：
  - `MinigameCfg`（小游戏定义）；
  - `MinigameActionCfg`（关卡）。
- 只读字典：`GuideCfg`（玩法说明）、`RelationCfg`（关系名）、`TalkCfg`（对白存在性）。
- 读取 `GET /api/cfg/<name>`（`data` + `mtime_ns`）；写回 `PUT` 带 `expect_mtime_ns`，
  409 逐表弹「重新加载 / 强制覆盖」。保存按 `MinigameCfg → MinigameActionCfg` 只写脏表。
- 「保存修改」写回脏表；「放弃修改」回滚到本次加载快照。

## 当前版本的边界

- **不做可玩复刻**：对标内嵌数独试玩；这里只做配置编辑与静态玩法说明，不渲染游戏画面。
- **不做「人物社交 / 原版 / 插件」分类筛选**：对标按 `PersonGrowCfg` 的 `minigame` 绑定与
  插件 id 归类；这里未引入该分类（避免误判），统一按 `MinigameCfg` 全表列出。
- **不做关卡用途绑定**：对标通过「外部对话」的用途系统把对话夹绑定到小游戏开场 / 胜利 /
  失败入口；这里只编辑 `startTalk/winTalk/loseTalk` 编号，不建绑定。
- **不做插件小游戏**：只处理原版社交 `MinigameCfg`。
- **不做小游戏配图导入**：只读取既有 `GuideCfg` 配图。
- **新建小游戏不会自动补齐全部 5 关**：默认只建第 1 关，其余按需添加。
