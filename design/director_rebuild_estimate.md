# 导演工作台 · 按功能重建专属界面 —— 存储与体积预估

> 目标：导演模式里每个功能都拥有**专属界面布局**（不再是套壳的通用 Schema 页），按功能逐个重建。
> 本文先给存储/体积/内存预估，供排期与取舍。

## 一、实测基线（本仓库 + 对标模块）

| 指标 | 数值 |
| --- | --- |
| `frontend/lib` 全部 Dart | 140 文件 · **2,717 KB** · 75,805 行 |
| `frontend/test` 全部 Dart | 92 文件 · **844 KB** · 22,827 行（测试/源码 ≈ 31%） |
| 最大功能簇 `lib/features/story` | 24 文件 · 900 KB（剧情处理 181KB + 剧情图工作区 138KB + 剧情舞台 131KB…） |
| 编译产物（web release）`main.dart.js` | **5.35 MB**（含 Flutter 框架常量） |
| 发行包 `web-app-*.zip` | **16.9 MB** |
| 发行包 `editor-server-linux-*.zip` | ~2.0 MB |
| `portrait_pack.zip`（人物图包，非代码） | 29.6 MB |
| 对标全部功能模块源码（JS/CSS 求和） | **≈ 988 KB**（含 workshop 118KB、scene 90KB、characters 119KB…） |
| 平均每行 Dart 源码 | ≈ 36 字节/行 |

**换算规则（保守）**
- Dart 源码量 ≈ 对标 JS+CSS 字节 × **1.5**（Dart 比 JS/模板字符串啰嗦），并复用现有数据/引擎层。
- 编译产物增量 ≈ 新增源码 × **0.5**（web 与 AOT 折中）。
- zip 压缩后增量 ≈ 编译产物 × **0.35**。
- 测试量 ≈ 功能源码 × **28%**。

## 三、合计

| 口径 | 估算 |
| --- | --- |
| **新增源码** | **≈ 1.6–2.3 MB**（≈ 45,000–62,000 行，新增 ~40–60 个文件） |
| 其中测试 | ≈ 0.35–0.5 MB |
| **编译产物增量** | ≈ **0.8–1.2 MB** |
| **web 发行 zip 增量** | ≈ **+0.3–0.5 MB**（16.9 MB → ≈ 17.2–17.4 MB，**+2%~3%**） |
| **桌面（Win/mac）包增量** | ≈ **+0.5–1.0 MB**（+1%~2%，主体是引擎+原生后端） |
| **Android APK 增量** | ≈ **+0.3–0.8 MB** |
| **Git 仓库增量** | 源码 ~2 MB；打对象后约 +0.5–0.8 MB |
| **常驻内存** | 基线不变（视图懒加载/Offstage 保活） |
| **峰值内存** | 同时保活若干专属视图时 **+10–40 MB**（图片/预览占大头） |

> 结论：**代码不是发行包的主要占用**。当前 `dist` 里最大的是 `portrait_pack.zip`(29.6MB) 与
> `web-app zip`(16.9MB)，全量重建只让发行包涨 **1%~3%**；真正需要担心的是**编译时间**与
> **常驻视图数量**，不是磁盘。

## 五、口径与风险

- 上述为**量级预估**（±30%）：Dart 与对标 JS 的表达密度不同，且能复用现有 Schema/数据/保存层，
  实际可能更省；若追求像素级复刻每个效果，可能更费。
- 运行内存只统计**新增视图**；图片解码与预览控件通常是内存主因，不是 Dart 代码量。
- 未计：后端(native C++)改动、新增静态素材（背景/立绘/音频）。素材若随包分发，**按 MB 级另计**。
- 未计：编译时长增长（每 +1 MB Dart 源码，release 构建时间线性增加，桌面 LTO 下更明显）。
