## 0. 截图直读：两边的「效果目录」差在哪

把两边同时打开，差异肉眼可见（左=友商，右=我们）：

| 差异 | 友商 #2 | 我们 |
| --- | --- | --- |
| 主行文案 | 「增减属性」「直接成为恋人」「获得物品」——纯人话 | 「属性 `@ATTR@` 增加 V」「移除状态 `@STATE@`」——占位符外露 |
| 副行 | 只有分类「改变属性」 | 分类 + **原始代码**「改变属性 · `[1, 1, @ATTR@, V]`」 |
| 概念折叠 | 「增减属性」**1 条** | 「增加 / 每回合增加 / 设为 / 增加 V 单位 / 增加时额外加 V」**5 条并列** |
| 分类 | 12 个白话分类（改变属性/改变技能/社交/空间/改变目标、抱负/UI…） | 3 个（全部/改变状态/改变属性，只取**当前页数据里出现过的**） |
| 布局 | 卡片网格，大标题 + 副分类，易扫读 | 密集列表 |
| 右栏 | 「已添加效果 N 项」实时编辑 | 无，只有「关闭」 |
| 其它 | ＋创建前提、取消/完成、122 项 | 无前提、40 项、关闭 |

**根因（不是风格问题，是数据契约问题）：** 我们的目录直接把后端 `desc`（含 `@ATTR@`/`V`/`@STATE@` 占位符）与 `code` 塞进列表行（`effect_slot_form.dart:542-554`），**没有"展示名"这一层**；同时后端返回的是扁平的 `EFFECT_DB` 候选（`semantic_routes.cpp:302-453`），**没有概念折叠**。所以修法是：后端补 `title`/`family`，前端目录只显示人话。

### 机制结论

**友商的选择器本质是"用一句人话描述一条指令、并在句子里就地改词"；我们的是"先从一个带占位符的代码模板清单里挑一条，再在另一个弹窗里按字母槽填参数"。**

差距不在"语言是不是中文"——我们的 `desc` 其实已经是中文（`semantic_db_data.cpp` 里 `"事件 V 已发生"`、`"解锁地点 @MAP@"`）。差距在**形态**：

| | 友商 #2 | 我们 |
| --- | --- | --- |
| 一个效果/条件 = | **一句话模板**（参数是句子里的词） | **一个含占位符字母的规则** + 一张参数表单 |
| 选与改 | 同一个面板，选完即就地改 | 两个弹窗：先选（`showEffectCatalogBrowser`）→ 再填（`showEffectSlotForm`） |
| 目录里一条概念 | 一条（算符行内循环） | 多条（`≥`/`≤`/范围各一条 desc） |
| 数字参数标签 | 自然短语（"变化量（负数为减少）"） | 统一"数值"（`semantic_graph.cpp:247`） |

## 1. 友商"更贴近自然语言"的 5 个机制

用真实模板说明（`effect-templates.json` / `condition-templates.json`）：

**① 一条概念一个入口，算符收进行内。**
友商条件模板只按"概念"建条目——"属性 ≥ 不低于""属性 < 低于"…在目录里被 `family()` 折叠成**一条「属性数值」**，算符变成行内一个可循环的按钮：`= > ≥ < ≤ ≠ 范围`（`condition-library.js:27-28,56`，`conditions.js:81-98`）。
我们的目录是**按算符铺开的多条候选**：`"年龄 >= V"`、`"年龄 <= V"`、`"X <= 年龄 <= Y"`（`semantic_db_data.cpp:13`）。用户面对的是"代码变体清单"而不是"概念清单"。

**② 行内成句，引用 ID 解析成人话。**
友商的整段摘要是 `summary()` 拼出来的句子（`conditions.js:30`）：
> `属性数值：语文 / 80，且 人物好感度：白雨 / ≥50，且 恋爱状态：有恋人`

它甚至为常见组合写了专门的句子（`恋爱状态：有恋人` / `恋爱关系：恋人是白雨`）。我们的行卡片是 `template.desc`（含 `@ATTR@`/`V` 占位）+ 原始 `code` 小字（`effect_block_editor.dart:129` 的 `toHumanText`）。

**③ 参数标签是自然短语，且嵌在句子里。**
友商每条参数自带人话标签："变化量（负数为减少）""持续回合（0用默认，−1不限）""另一项（任一满足，0 表示不指定）"（`effect-templates.json` / `condition-templates.json`），控件就落在句子对应位置。
我们的数字槽标签统一是 `"数值"`（`semantic_graph.cpp:247`），编辑形态是表单里的一行 `V（数值） [____]`（`effect_slot_form.dart:241`）。

**④ 白话分类 + 每个模板一句说明。**
友商把官方类型折叠成白话分组——"时间与概率 / 剧情与事件 / 属性与状态 / 技能与学习 / 社交与恋爱 / 行动与目标 / 物品 / 其他"（`conditions.js:49-53`），效果分类同理；面板顶部还有引导语"多条条件需要全部满足""增减属性时，正数为增加，负数为减少"（`condition-library.js:14`，`effects.js:19`）。我们直接用 `ConditionTypeCfg` 名，兜底成"类型 N"（`block_catalog.dart`）。

**⑤ 没模板的规则给"原版用法"样本。**
未收录规则不是甩一个原始参数框，而是列出**真实用例**（人话标题 + 原始数组）供复制（`condition-library.js:33,58`）。

## 3. 同一个效果，两边怎么操作

**目标：给一句对白加「语文 +10」**

- **友商**：点"＋ 添加效果"→ 目录里点「增减属性」→ 右侧立刻出现一行
  `增减属性  [属性 ▾ 语文]  [变化量（负数为减少）: 10]` → 完成。
  或直接点目录里的「语文」tile（按属性展开），得到 `[属性=语文][0]` 再改数值。
- **我们**：字段点"打开积木库"→ 目录里翻到候选 `改变属性 @ATTR@ +V` → 点它 → **弹出第二个对话框**，逐行填 `@ATTR@（属性）[选择…]`、`V（数值）[___]` → 确定 → 回到积木行，看到人话 + 代码小字。

**目标：条件「人物好感 ≥ 50」**

- **友商**：点「人物好感度」（6 个算符已折叠成 1 条）→ 右侧 `人物好感度 [人物 ▾ 白雨] [≥] [50]`，点 `≥` 在 `= > ≥ < ≤ ≠ 范围` 间循环。
- **我们**：目录里有 `好感 >= V`、`好感 <= V`、`好感 > V`… 多条独立候选，选一条后再弹表单填"人物"和"数值"。

### 4.3 一点澄清：字段覆盖

我写脚本核对了第三方 schema（`catalog-schema.json`）里**所有标注为 Effect/Condition 的数组字段**，我们的码字段判定（`field_meta.dart:388-477`）**0 漏网**。仅两个非数组字段被我们的类型门挡住：`KZoneProfileCfg:living`（string，友商标 Condition）、`EndingOptionCfg:part`（number，友商标 Effect）。
但我们的判定是**手写白名单 + key 命名启发式**，历史上多次需要补登（`field_meta.dart:407-420` 注释即证据）。友商是**schema `editorType` 驱动**，新增字段自动覆盖——机制上更稳，值得换成 schema 驱动。

## 5. 改造方案

### 主题 A：把选择器"语言化"（对应 §2 的 1-5、7-11）

1. **后端补"语义元数据"**（一次下沉、三端共享）：在 `effect_suggest` 的 item 与 `effect/parse` 的 `row.template` 上增加
   - `family`：稳定概念键（`attribute`/`favor`/`age`/…）；
   - `ops[]`：`{op, code, valueIndex, upperIndex}`，让前端把算符收进行内；
   - 参数级 `label`/`min`/`max`/`step`/`unit`/`choices`；
   - 模板级 `description`（"这个模板在干什么"的白话说明）。
   来源：`semantic_db_data.cpp` 的 `CONDITION_DB/COST_DB` 二次索引 + 现有模板数据。
2. **前端"一条概念一行"**：目录按 `family` 折叠，行内渲染 `= > ≥ < ≤ ≠ 范围` 算符按钮与范围上下限（对标 `condition-library.js:56`）。
3. **行内成句**：已添加清单每行渲染 `summary` 式句子（引用 ID→名称），多条用"，且"连接（对标 `conditions.js:30`）。
4. **自然参数标签**：数字槽用参数级 `label` 替换统一"数值"；补 min/max/step 即时校验并**禁用"完成"**（对标 `effects.js:8,45`）。
5. **白话分类 + 说明**：补分组名与 `foldSingles`；目录顶部/模板下方放说明与引导语。
6. **未收录规则**："原版用法"样本下拉（依赖主题 B 的索引）。
7. **初始值**：新增候选时自动选第一个合法引用，无可用引用给友好错误（对标 `effects.js:7`）。
8. **快捷 tile**：按 `PersonAttrCfg` 展开属性 tile；MBTI 专用控件。

### 主题 B：复用与效率（对应 §4.1）

1. **已有条件/效果索引**：后端扫工作区各表 code 字段，去重 + 用量 + 来源（本模组/其他模组/原版），缓存后台生成（对标 `condition_library.py:23-88`）。
2. **前提库**：存编辑器状态，序列化为原生数组（talk 达成 `[3,3,talk]`、事件值 `[111,1,event,slot,1]`），改名同步 + 引用扫描（对标 `condition_library.py:91-106`）。
3. **条件配置（预设）**：模组级 + 用户级，原子写/文件锁（对标 `condition_library.py:208-268`）。
4. **搜索升级**：拼音/首字母 + 无命中回退"已有组合"（对标 `search.js:5-9`）。

### 主题 C：补齐界面（对应 §4.2）

1. **人物动作可视化编辑器**：动作列表 + 实时预览 + 播放/播放全部 + 参数面板 + 舞台拖拽 + 延迟（对标 `action-editor.js`）；可先做"预览 + 参数面板"，拖拽/播放其次。
2. **事件绑定表单化**：社交/送礼/互动用表单填，自动派生条件/效果（对标 `event-bindings.js`）。

### 主题 D：机制加固

- 码字段判定改 **schema `editorType` 驱动**（用已有 `catalog-schema.json` 作单一事实源，替换 `field_meta.dart` 手写白名单）。
- `singleRow`（一句话一屏效）三处判定收敛为单点（`effect_block_editor.dart:386,429`、`block_library.dart:744`、`semantic_graph.cpp:459`）。
- 嵌套 998 子行补齐增/删/移/复制，或明确只读说明（`effect_block_editor.dart:774`）。

## 7. 验收与守门

- **A1**：后端单测——同一概念在 `effect_suggest`/`effect/parse` 返回一致的 `family`/`ops[]`；参数 `label` 来自模板而非统一"数值"。
- **A2/A3**：widget 测试——目录按概念折叠；算符点击改写 code 且保留已填值；范围生成 `[1,3,X,Y]`；摘要含引用名与"，且"。
- **A4**：非法数值禁用"完成"；min/max/step 边界用例。
- **A7**：新增候选自动带出第一个合法引用；无引用时给出可读错误。
- **B1**：后端扫描去重/用量/来源/缓存；搜索无命中回退"已有组合"。
- **B2/B3**：前提序列化往返（`[3,3,talk]`/`[111,1,event,slot,1]`）、改名同步、引用扫描；预设保存/读取/删除 + 文件锁。
- **C1**：动作面板参数写回 `roles`；预览渲染不崩。
- **D**：schema 驱动判定覆盖全表（对照 `catalog-schema.json` 的 `editorType`）；既有 `frontend/test/blocks_library_test.dart` 等防回归。
- 三端：后端元数据/端点变更同步更新 `CLI_TUI_GUIDE.md` 与 TUI/CLI 提示逻辑（`native/tui/p8_api.cpp:842`、`native/cli/p7_repl.cpp:955`）。

## 8. 边界（本轮不做）

- 不做自由布尔树：友商也是"列表=全满足 + 分支顺序路由"（`condition-library.js:14`），沿用即可。
- 不做友商视觉的像素级复刻：只吸收"自然语言化"的交互范式，视觉走现有工作台骨架与主题 token。
- 友商纯 Web，我们 GUI + CLI + TUI 三端：能把语义元数据下沉后端的优先下沉。
